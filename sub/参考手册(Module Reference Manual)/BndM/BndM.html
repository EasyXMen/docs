术语与简写(Terms and Abbreviations)¶

术语(Term)¶

术语(Term)

解释(Explain)

BlockDescriptor

BndM应在直接可访问内存中管理其BndM块。 The BndM shall manage its BndM blocks in the direct accessible memory.

WriteStartPhase

调用BndM_WriteStart将触发第二个（空闲）分区的准备。 A call of BndM_WriteStart shall trigger the preparation of the 2nd (free) partition.

WriteBlockPhase

调用BndM_WriteBlock将触发将数据写入第二个（未使用的）分区。不应该修改数据（ImplementationDataType）以允许指针访问。 A call of BndM_WriteBlock shall trigger the writing of the data to the 2nd (unused) partition. The data (ImplementationDataType) shall be not modified to allow a pointer access.

WriteFinalizePhase

调用BndM_WriteFinalize将触发第二个（未使用的）分区的结束。在后台，BndM通过将所有未更改的BndMBlockDescriptor复制到第二个（未使用的）分区，使第二个（未使用的）分区保持一致。如果最终化成功，BndM将使第二个（未使用的）分区变为活动分区，并触发回调Xxx_BndMWriteFinalizeFinish，结果设置为E_OK。 A call of BndM_WriteFinalize shall trigger the finalization of the 2nd (unused) partition. In background the BndM shall make the 2nd (unused) partition consistent by coping all unchanged BndMBlockDescriptor to the 2nd (unused) partition.  If the finalization is successful the BndM shall make the 2nd (unused) partition to the active partition and trigger the callback Xxx_BndMWriteFinalizeFinish with the result set to E_OK.

简介(Introduction)¶

对于变体编码（variant-coding）等用例场景，对于非易失性大容量数据的需求正在增加。此类数据经常使用，但很少更新。与NvM相比，BndM提供了一个 API来直接从Flash存储单元中读取数据。带来的好处就是避免了RAM镜像，但缺点就是数据的写入会更加复杂。

For use case scenarios such as variable-coding, the demand for non-volatile large-capacity data is increasing. Such data is frequently used but rarely updated. Compared with NvM, BndM provides an API to directly read data from Flash storage units. The advantage it brings is that it avoids RAM mirroring, but the disadvantage is that data writing will be more complicated.

变体编码（Variant coding）是车辆特定的数据集，它在每辆车的生产过程中计算并生成，当然也在生产过程中保存。

Variant coding is a vehicle-specific dataset that is calculated and generated during the production process of each vehicle and, of course, is also saved during the production process.

BndM模块是AUTOSAR中用于处理大批量非易失性数据（NvData）存储和管理的关键模块；BndM 通过提供批量数据存储和恢复功能，增强了系统的可靠性和数据一致性。

The BndM module is a key module in AUTOSAR for processing the storage and management of large volumes of non-volatile data (NvData). BndM enhances the reliability of the system and data consistency by providing batch data storage and recovery functions.

如图 BndM模块层次图 所示，BndM模块处于AUTOSAR软件架构中的通信栈服务层，BndM模块与存储栈抽象层的MemAcc组件进行交互，与诊断栈服务层的Dcm/Det组件进行交互。 As shown in the figure :ref: ‘BndM Module Hierarchy Diagram’, the BndM module is located in the communication stack service layer of the AUTOSAR software architecture. The BndM module interacts with the MemAcc component in the storage stack abstraction layer and the Dcm/Det component in the diagnostic stack service layer.

编程基本原理：Program Basic Principles of BndM¶

基本思想是对数据块进行A/B分区切换。意味着完整的非易失性大容量数据（Bulk Nv Data）将存储在分区A中。当写入动作开始时（BndM_WriteStart），B分区需要被擦除。更新的数据块（BndM_WriteBlock）将被写入到分区B。最终确定阶段（BndM_WriteFinalize）将使分区B保持一致（通过将未更新的块复制到分区B）并将激活分区切换到B（进一步调用BndM_GetBlockPtr将指向分区B中的数据）。 The basic idea is to perform A/B partition switching on data blocks. It means that the complete non-volatile Bulk Nv Data will be stored in partition A. When the write operation begins (BndM_WriteStart), partition B needs to be erased. The updated data block (BndM_WriteBlock) will be written to partition B. The final determination phase (BndM_WriteFinalize) will keep partition B consistent (by copying the unupdated block to partition B) and switch the active partition to B (further calls to BndM_GetBlockPtr will point to the data in partition B).

编程序列(Programming Sequence)

功能描述(Function Description)

WriteStart
写入准备阶段(Write preparation phase)：

  1. BndM模块的上层组件通过调用BndM_WriteStart函数接口，向BndM模块发起一个写入作业的请求任务； The upper-level component of the BndM module initiates a request task for a write job to the BndM module by calling the BndM_WriteStart API.

  2. BndM模块获取A-B两个分区的激活状态和版本控制信息；相对而言，当前A分区处于激活状态，B分区处于未激活状态； The BndM module acquires the activation status and version control information of partitions A and B. Relatively speaking, currently partition A is in an active state, while partition B is in an inactive state.

  3. BndM模块通过调用MemAcc组件的MemAcc_Erase函数接口，对未激活分区B执行擦除操作； The BndM module performs an erase operation on the inactive partition B by calling the MemAcc_Erase API of the MemAcc component.

  4. BndM模块通过调用MemAcc组件的MemAcc_GetJobResult/MemAcc_GetJobStatus函数接口，获取擦除操作的作业结果/状态； The BndM module acquires the job result/status of the erasure operation by calling the MemAcc_GetJobResult /MemAcc_GetJobStatus API of the MemAcc component.

  5. 如果检测到擦除作业异常，则通过调用可配置Xxx_BndMWriteStartFinish(result = E_NOT_OK)函数接口，向上层组件通知BndM写入准备错误的反馈状态，并立即释放资源，结束本次写入作业任务； If an anomaly of the erase job is detected, the feedback status of the BndM write preparation error is notified to the upper component by calling the configurable Xxx_BndMWriteStartFinish(result = E_NOT_OK) API, and the resources are immediately released to end this write job task.

  6. 如果检测到擦除作业正常，则通过调用可配置Xxx_BndMWriteStartFinish(result = E_OK)函数接口，向上层组件通知BndM写入准备成功的反馈状态，并通知上层允许执行下一个阶段的作业任务。 If it is detected that the erasure job is normal, then by calling the configurable Xxx_BndMWriteStartFinish(result = E_OK) API, notify the upper-layer component of the feedback status that the BndM write preparation is successful, and notify the upper-layer to allow the execution of the next stage of the job task.

WriteBlock
写入数据阶段(Data Writing Stage)：

  1. BndM模块的上层组件通过调用BndM_WriteBlock函数接口，请求BndM模块开始执行编程任务。 The upper-level components of the BndM module request the BndM module to start performing programming tasks by calling the BndM_WriteBlock API.

  2. BndM模块通过调用MemAcc组件的MemAcc_Write函数接口，对未激活分区B待更新Block块执行编程操作。 The BndM module performs programming operations on the unactivated Block B to be updated by calling the MemAcc_Write API of the MemAcc component.

  3. BndM模块通过调用MemAcc组件的MemAcc_GetJobResult/MemAcc_GetJobStatus函数接口，获取编程操作的作业结果/状态； The BndM module acquires the job result/status of the programming operation by calling the MemAcc_GetJobResult/MemAcc_GetJobStatus API of the MemAcc component.

  4. 如果检测到编程作业异常，则通过调用可配置Xxx_BndMWriteBlockFinish(result = E_NOT_OK)函数接口，向上层组件通知BndM写入数据错误的反馈状态，并立即释放资源，结束本次写入作业任务； If an abnormal programming job is detected, the feedback status of the BndM writing data error is notified to the upper-layer component by calling the configurable Xxx_BndMWriteBlockFinish(result = E_NOT_OK) API, and resources are immediately released to end this writing job task.

  5. 如果检测到编程作业正常，则通过调用可配置Xxx_BndMWriteBlockFinish(result = E_OK)函数接口，向上层组件通知BndM写入数据成功的反馈状态，并通知上层允许执行下一个阶段的作业任务。 If it is detected that the programming job is normal, by calling the configurable Xxx_BndMWriteBlockFinish(result = E_OK) API, the feedback status of BndM writing data successfully is notified to the upper component, and the upper component is informed that the job task of the next stage is allowed to be executed.

WriteFinalize
写入收尾阶段(Write to the finishing stage)：

  1. BndM模块的上层组件通过调用BndM_WriteFinalize函数接口，请求BndM模块开始执行终结任务。 The upper-level components of the BndM module request the BndM module to start the finalization task by calling the BndM_WriteFinalize API.

  2. 对未激活分区B未使用的Block块，需要从A激活分区拷贝对应Block块的数据，重复以上编程作业任务，将拷贝的数据写入到未激活分区B对应Block的内存单元中。 For the unused blocks in unactivated partition B, it is necessary to copy the data of the corresponding Block from the activated partition A. Repeat the above programming task and write the copied data to the memory unit of the corresponding Block in unactivated partition B.

  3. BndM模块通过调用MemAcc组件的MemAcc_Write函数接口，对未激活分区B的“编程标签-版本控制信息”执行更新编程操作。 The BndM module performs an update programming operation on the “programming Label - version control information” of the inactive partition B by calling the MemAcc_Write API of the MemAcc component.

  4. BndM模块通过调用MemAcc组件的MemAcc_GetJobResult/MemAcc_GetJobStatus函数接口，获取编程操作的作业结果/状态； The BndM module acquires the job result/status of the programming operation by calling the MemAcc_GetJobResult/MemAcc_GetJobStatus API of the MemAcc component.

  5. 如果检测到编程作业异常，则通过调用可配置Xxx_BndMWriteFinalizeFinish(result = E_NOT_OK)函数接口，向上层组件通知BndM写入终结错误的反馈状态，并立即释放资源，结束本次写入作业任务； If an abnormal programming job is detected, the feedback status of the BndM write termination error is notified to the upper-layer component by calling the configurable Xxx_BndMWriteFinalizeFinish(result = E_NOT_OK) API, and resources are immediately released to end this write job task.；

  6. 如果检测到编程作业正常，则通过调用可配置Xxx_BndMWriteFinalizeFinish(result = E_OK)函数接口，向上层组件通知BndM写入终结成功的反馈状态，并通知上层允许执行下一个阶段的作业任务。 If it is detected that the programming job is normal, by calling the configurable Xxx_BndMWriteFinalizeFinish(result = E_OK) API, the feedback status of the successful completion of BndM writing is notified to the upper-level component, and the upper-level component is informed that the job task of the next stage is allowed to be executed.

  7. 将A-B分区的激活状态进行切换，并立即释放资源，结束本次写入作业任务。 Switch the activation status of partitions A-B and immediately release the resources to end this write job task.

  8. BndM模块的上层组件通过调用BndM_GetBlockPtr函数接口，从BndM模块指定地址的内存单元中获取数据，并对数据进行校验，来判决本次写入作业是否更新成功。 The upper-layer components of the BndM module get data from the memory unit at the specified address of the BndM module by calling the BndM_GetBlockPtr API and verify the data to determine whether the current write job has been updated successfully.

基于BndM组件的存储控制机制（Storage control mechanism based on BndM components）¶

如图 BndM模块的存储控制机制图 所示，BndM模块的批量数据写入请求大致分为三个阶段，写入准备阶段，写入数据阶段，写入收尾阶段，并且写入作业的控制完全受制于MemAcc的控制流程。 As shown in the figure :ref: ‘Storage Control Mechanism Diagram of BndM Module’, the batch data write requests of BndM module are roughly divided into three stages: write preparation stage, write data stage, and write closure stage. Moreover, the control of write jobs is completely subject to the control flow of MemAcc.

如图 BndM模块的存储栈交互关联关系图 所示，BndM模块的上层与Dcm模块进行交互，一般用于UDS-WriteDataByDID，下层直接与MemAcc模块进行交互，间接对底层Flash存储单元执行写入操作。 As shown in the figure :ref: ‘The storage Stack Interaction Association Diagram of the BndM module’, the upper layer of the BndM module interacts with the Dcm module, which is generally used for UDS-WriteDataByDID, and the lower layer directly interacts with the MemAcc module, indirectly performing write operations on the underlying Flash storage unit.

如图 BndM模块的存储栈API关联关系图 所示，BndM模块的上层Dcm模块调用BndM_WriteStart/BndM_WriteBlock/BndM_WriteFinalize等接口来请求写入作业，并通过Xxx_BndMWriteStartFinish/Xxx_BndMWriteBlockFinish/Xxx_BndMWriteFinalizeFinish回调函数的通知，来获取每一个阶段的作业结果；BndM模块调用下层的MemAcc_Erase/MemAcc_Write/MemAcc_GetJobResult/MemAcc_GetJobStatus来完成内存块的擦除&编程的作业任务。 As shown in the figure :ref: ‘The API Association Diagram of the BndM module’s storage stack’, the upper-layer Dcm module of the BndM module calls interfaces such as BndM_WriteStart/BndM_WriteBlock/BndM_WriteFinalize to request write jobs And obtain the job results of each stage through the notification of the callback functions Xxx_BndMWriteStartFinish/Xxx_BndMWriteBlockFinish/Xxx_BndMWriteFinalizeFinish; The BndM module calls the lower-level MemAcc_Erase/MemAcc_Write/MemAcc_GetJobResult/MemAcc_GetJobStatus to complete the memory block erasure and programming job tasks.

基于BndM组件的块描述访问（Block description access based on BndM components）¶

  1. BndM模块能够通过指针的方式直接访问内存中管理的BndMBlockDescriptor块。 The BndM module can directly access the BndMBlockDescriptor block managed in memory through a pointer.

  2. BndM_GetBlockPtr的函数调用能够将基指针传递给当前激活分区中相应的BndMBlockDescriptor块。 The function call of BndM_GetBlockPtr can pass the base pointer to the corresponding BndMBlockDescriptor block in the currently activated partition.

  3. 函数实现隐藏目的：用于从非易失性存储单元中读取BndM块的数据；读取操作就跟访问RAM的方式一样，可以直接通过指针的方式获取。 The function implements a hidden purpose: it is used to read the data of BndM blocks from non-volatile storage units. The reading operation is just like accessing RAM and can be directly obtained through a pointer.

基于BndM组件的写入准备描述（Write preparation description based on BndM components）¶

  1. BndM_WriteStart的函数调用将触发第二个（空闲）分区的准备；对分区执行擦除操作。 The function call of BndM_WriteStart will trigger the preparation of the second (idle) partition; Perform an erase operation on the partition.

  2. 在成功完成第二个（空闲）分区的准备后,可以写入第二个分区，并通过异步操作在BndM_MainFunction的上下文中调用回调函数Xxx_BndMWriteStartFinish，并将结果设置为E_OK。 After successfully completing the preparation of the second (idle) partition, the second partition can be written, and the callback function Xxx_BndMWriteStartFinish can be called in the context of BndM_MainFunction through asynchronous operations, and the result is set to E_OK.

  3. 如果BndM_WriteStart的函数调用处于已激活写入阶段（BndM_WriteStart和BndM_WriteFinalize之间的阶段），则BndM_WriteStart的函数调用将会被拒绝，并且错误代码会被设置为E_NOT_OK。 If the function call of BndM_WriteStart is in the activated write phase (the phase between BndM_WriteStart and BndM_WriteFinalize), the function call of BndM_WriteStart will be rejected and the error code will be set to E_NOT_OK.

基于BndM组件的写入数据描述（Write data description based on BndM components）¶

  1. BndM_WriteBlock的函数调用能够触发将数据写入第二个（未使用的）分区；ImplementationDataType类型的数据不允许通过指针访问并被修改。 The function call of BndM_WriteBlock can trigger the writing of data to the second (unused) partition. Data of the ImplementationDataType type is not allowed to be accessed and modified through Pointers.

  2. 在第二个（空闲）分区的写入完成后，并通过异步操作在BndM_MainFunction的上下文中调用回调函数Xxx_BndMWriteBlockFinish，并将结果设置为E_OK。 After the write to the second (idle) partition is completed, call the callback function Xxx_BndMWriteBlockFinish in the context of BndM_MainFunction through an asynchronous operation, and set the result to E_OK.

  3. 如果在先前BndM_WriteStart函数未曾调用的情况下，则BndM_WriteBlock函数的调用将被拒绝，并将错误代码设置为E_NOT_OK。 If the BndM_WriteStart function has not been called before, the call to the BndM_WriteBlock function will be rejected and the error code will be set to E_NOT_OK.

  4. 如果BndM_WriteBlock函数的调用是在另一个相同的或另一个块正在写的时候完成的，则BndM_WriteBlock函数的调用将被拒绝，并将错误码设置为E_NOT_OK。 If the call to the BndM_WriteBlock function is completed when another identical or another block is being written, the call to the BndM_WriteBlock function will be rejected and the error code will be set to E_NOT_OK.

  5. 如果BndM_WriteBlock函数的调用是在BndM的终结模式内或之后进行的，则BndM_WriteBlock函数的调用将被拒绝，并将错误码设置为E_NOT_OK。 If the call of the BndM_WriteBlock function is made within or after the terminal mode of BndM, the call of the BndM_WriteBlock function will be rejected and the error code will be set to E_NOT_OK.

基于BndM组件的写入收尾描述（Write closure description based on BndM components）¶

  1. BndM_WriteFinalize函数的调用将触发第二个（未使用的）分区的最终化工作（finalization）。在后台通过异步操作方式，BndM能够将所有未更改的BndMBlockDescriptor复制到第二个（未使用的）分区来使第二个（未使用的）分区的数据保持一致。 The call to the BndM_WriteFinalize function will trigger the finalization of the second (unused) partition. In the background, through asynchronous operation mode, BndM can copy all the unaltered BNDMBlockdescriptors to the second (unused) partition to keep the data in the second (unused) partition consistent.

  2. 如果最终确定成功，BndM能够将第二个（未使用的）分区设为激活分区，并调用回调函数 Xxx_BndMWriteFinalizeFinish，并将结果设置为E_OK。 If it is finally confirmed to be successful, BndM can set the second (unused) partition as the activation partition and call the callback function Xxx_BndMWriteFinalizeFinish, and set the result to E_OK.

  3. 如果最终确定不成功，则会因为第二个分区数据不一致，导致数据不能使用；BndM应将当前激活分区保持为激活分区，并触发回调Xxx_BndMWriteFinalizeFinish，并将结果设置为E_NOT_OK。 If it is ultimately determined to be unsuccessful, the second partition data will be inconsistent, resulting in the data being unusable. BndM should keep the current activation partition as the activation partition, trigger the callback Xxx_BndMWriteFinalizeFinish, and set the result to E_NOT_OK.

  4. 在先前BndM_WriteStart函数未被调用的情况下，或者BndM已经在最终化模式（finalization mode）中，当检测到BndM_WriteFinalize函数被调用，则BndM_WriteFinalize函数将抛出一个BNDM_E_WRONG_SEQUENCE的DET错误。 In the case where the BndM_WriteStart function was not called previously, or BndM was already in the finalization mode, when it was detected that the BndM_WriteFinalize function was called, Then the BndM_WriteFinalize function will throw a DET error of BNDM_E_WRONG_SEQUENCE.
