简介(Introduction)¶

PduR模块主要为通信接口模块(如CanIf)，传输协议模块(如CanTp)，诊断服务模块(如Dcm)，通信服务模块(如Com, LdCom)，以及IpduM，SecOc等模块提供基于PDU的路由服务。PduR模块主要实现基于PDU的接收路由(PDU从CanIf→PduR→Com)，发送路由(Com→PduR→CanIf)，网关路由功能(CanIf→PduR→CanIf)。

The PduR module provides PDU-based routing services for communication interface modules (e.g., CanIf), transport protocol modules (e.g., CanTp), diagnostic service modules (e.g., Dcm), communication service modules (e.g., Com, LdCom), as well as modules such as IpduM and SecOc. The PduR module implements PDU-based reception routing (PDU from CanIf→PduR→Com), transmission routing (Com→PduR→CanIf), and gateway routing (CanIf→PduR→CanIf).

与PduR模块存在交互的模块可分为三类：1.下层模块(如CanIf, CanTp)；2.上层模块(如Com, Dcm)；3.既是上层又是下层模块(IpduM, SecOC)。 PduR与所有交互模块间实现IF PDU和TP PDU的接收与发送功能。

Modules interacting with the PduR module fall into three categories: 1. Lower-layer modules (e.g., CanIf, CanTp); 2. Upper-layer modules (e.g., Com, Dcm); 3. Modules serving as both upper and lower layers (IpduM, SecOC). The PduR module handles reception and transmission of IF PDUs and TP PDUs with all interacting modules.

模块特性（Module Features）¶

发送路由功能(Transmit Routing Function)¶

PduR发送链路(Transmit Path)负责将上层模块(如Com、Dcm、LdCom等)的Tx PDU路由到下层通信接口模块(如CanIf)或传输协议模块(如CanTp)。

The PduR transmit path routes Tx PDUs from upper-layer modules (e.g., Com, Dcm, LdCom) to lower-layer communication interface modules (e.g., CanIf) or transport protocol modules (e.g., CanTp).

Tx PDU的发送分为两种方式(IF和TP)：

Tx PDU transmission operates in two modes (IF and TP):

IF PDU发送(IF PDU Transmission)¶

上层模块通过调用 PduR_<Up>Transmit 接口发起IF PDU发送请求。PduR根据配置的PduRRoutingPath（PduRRouteType为IF）查找对应的PduRDestPdu，通过 PduR_<Lo>TxConfirmation 通知上层发送结果。

The upper-layer module initiates IF PDU transmission by calling PduR_<Up>Transmit. PduR looks up the corresponding PduRDestPdu based on the configured PduRRoutingPath (PduRRouteType = IF), and notifies the upper layer of the transmission result via PduR_<Lo>TxConfirmation.

  • 支持1:1和1:N路由（一个SrcPdu可路由到多个DestPdu）

    Supports 1:1 and 1:N routing (one SrcPdu can be routed to multiple DestPdus)

  • 如果PduRDestPdu关联的Tx PDU发送方式为TriggerTransmit，下层模块通过调用 PduR_<Lo>TriggerTransmit 请求上层提供发送数据

    If the Tx PDU transmission mode associated with PduRDestPdu is TriggerTransmit, the lower-layer module requests the upper layer to provide transmission data via PduR_<Lo>TriggerTransmit

  • 支持发送确认机制，上层通过 PduR_<Lo>TxConfirmation 获取发送结果

    Supports transmission confirmation; the upper layer obtains the transmission result via PduR_<Lo>TxConfirmation

TP PDU发送(TP PDU Transmission)¶

上层模块通过调用 PduR_<Up>Transmit 发起TP PDU发送请求。PduR根据配置的PduRRoutingPath（PduRRouteType为TP）查找对应的PduRDestPdu，下层TP模块通过 PduR_<LoTp>CopyTxData 分片获取PDU发送数据，通过 PduR_<LoTp>TxConfirmation 通知发送结果。

The upper-layer module initiates TP PDU transmission by calling PduR_<Up>Transmit. PduR looks up the corresponding PduRDestPdu based on the configured PduRRoutingPath (PduRRouteType = TP). The lower-layer TP module retrieves PDU transmission data segments via PduR_<LoTp>CopyTxData and notifies the transmission result via PduR_<LoTp>TxConfirmation.

  • 支持1:1和1:N路由

    Supports 1:1 and 1:N routing

  • 支持发送取消（通过 PduR_<LoTp>CancelTransmit）

    Supports transmission cancellation (via PduR_<LoTp>CancelTransmit)

  • TP PDU的发送过程中，PduR不缓存完整TP报文数据，而是通过CopyTxData机制按需向上层获取数据段

    During TP PDU transmission, PduR does not buffer the complete TP message data but retrieves data segments from the upper layer on demand via the CopyTxData mechanism

接收路由功能(Receive Routing Function)¶

PduR接收链路(Receive Path)负责将下层通信接口模块(如CanIf)或传输协议模块(如CanTp)接收到的Rx PDU路由到上层模块(如Com、Dcm、LdCom等)。

The PduR receive path routes Rx PDUs received from lower-layer communication interface modules (e.g., CanIf) or transport protocol modules (e.g., CanTp) to upper-layer modules (e.g., Com, Dcm, LdCom).

Rx PDU的接收分为两种方式(IF和TP)：

Rx PDU reception operates in two modes (IF and TP):

IF PDU接收(IF PDU Reception)¶

下层IF模块(如CanIf)通过调用 PduR_<Lo>RxIndication 将接收到的IF PDU传递给PduR。PduR根据配置的PduRRoutingPath（PduRRouteType为IF）查找对应的PduRDestPdu，将PDU数据路由到对应的上层模块。

The lower-layer IF module (e.g., CanIf) passes the received IF PDU to PduR via PduR_<Lo>RxIndication. PduR looks up the corresponding PduRDestPdu based on the configured PduRRoutingPath (PduRRouteType = IF) and routes the PDU data to the corresponding upper-layer module.

  • 支持1:1、1:N和N:1路由（多个SrcPdu可路由到同一个DestPdu）

    Supports 1:1, 1:N, and N:1 routing (multiple SrcPdus can be routed to the same DestPdu)

  • 接收链路不缓存IF PDU数据，直接从下层模块传递到上层模块

    The receive path does not buffer IF PDU data; it passes directly from the lower-layer module to the upper-layer module

TP PDU接收(TP PDU Reception)¶

下层TP模块(如CanTp)通过 PduR_<LoTp>StartOfReception 开始TP PDU接收流程，通过 PduR_<LoTp>CopyRxData 分片传递接收数据，最终通过 PduR_<LoTp>RxIndication 将完整TP PDU路由到上层模块。

The lower-layer TP module (e.g., CanTp) starts the TP PDU reception process via PduR_<LoTp>StartOfReception, passes received data segments via PduR_<LoTp>CopyRxData, and finally routes the complete TP PDU to the upper-layer module via PduR_<LoTp>RxIndication.

  • 支持1:1和1:N路由

    Supports 1:1 and 1:N routing

  • 支持接收取消（通过 PduR_<LoTp>CancelReceive）

    Supports reception cancellation (via PduR_<LoTp>CancelReceive)

  • TP PDU接收过程中，PduR不缓存TP报文数据，通过CopyRxData机制由下层模块按需向上层传递数据段

    During TP PDU reception, PduR does not buffer TP message data; data segments are passed from the lower layer to the upper layer on demand via the CopyRxData mechanism

网关路由功能(Gateway Routing Function)¶

PDU的网关同样分为IF/TP两种方式，IF网关支持1:1、1:N、N:1路由，TP网关也支持1:1、1:N、N:1路由，不涉及任何报文数据的变化，收发报文速率保持一致(如果目的端报文长度小于源端报文长度，会进行截断以确保网关功能正常)。 需注意PDU的网关不能IF、TP混用，即接收的IF PDU只能通过发送IF PDU进行转发，接收的TP PDU只能通过发送TP PDU进行转发。

PDU gateway operation is also divided into IF/TP modes. The IF gateway supports 1:1, 1:N and N:1 routing, and the TP gateway also supports 1:1, 1:N and N:1 routing. This process does not modify message data, and transmission/reception rates remain consistent (if the destination message length is shorter than the source message length, truncation occurs to ensure successful gateway operation). Note that PDU gateways cannot mix IF and TP modes: received IF PDUs can only be forwarded via transmitted IF PDUs, and received TP PDUs can only be forwarded via transmitted TP PDUs.

路由控制功能(Routing Control Function)¶

PduR的路由控制以RoutingPathGroup为单位进行启用/禁用控制，而PduRRoutingPath通过PduRRoutingPathGroupRef可以关联N个RoutingPathGroup，只要关联的至少一个RoutingPathGroup启用，则对应的PduRDestPdu使能。

PduR routing control enables/disables RoutingPathGroups as units. PduRRoutingPath can associate with N RoutingPathGroups via PduRRoutingPathGroupRef. The corresponding PduRDestPdu is enabled when at least one associated RoutingPathGroup is enabled.

偏差(Deviation)¶

  1. 不支持Tp多播发送（仅支持Tp多播接收）

    PduR does not support Tp multicast transmission (only Tp multicast reception is supported).

  2. 不支持PduRDemEventParameterRef

    PduR does not support PduRDemEventParameterRef.

  3. 自定义配置项PduRRouteType(IF/TP)

    Custom configuration item PduRRouteType (IF/TP)

PduR_TpCopyTxData¶

BufReq_ReturnType PduR_TpCopyTxData(PduIdType id, const PduInfoType *info, const RetryInfoType *retry, PduLengthType *availableDataPtr)

This function is called to acquire the transmit data of an I-PDU segment (N-PDU). Each call to this function provides the next part of the I-PDU data unless retry->TpDataState is TP_DATARETRY. In this case the function restarts to copy the data beginning at the offset from the current position indicated by retry->TxTpDataCnt. The size of the remaining data is written to the position indicated by availableDataPtr.

Sync/Async

Synchronous

Reentrancy

Reentrant

Parameters

Dir

Name

Description

[in]

id

Identification of the transmitted I-PDU.

[in]

info

Provides the destination buffer (SduDataPtr) and the number of bytes to be copied (SduLength). If not enough transmit data is available, no data is copied by the upper layer module and BUFREQ_E_BUSY is returned. The lower layer module may retry the call. An SduLength of 0 can be used to indicate state changes in the retry parameter or to query the current amount of available data in the upper layer module. In this case, the Sdu DataPtr may be a NULL_PTR.

[in]

retry

This parameter is used to acknowledge transmitted data or to retransmit data after transmission problems. If the retry parameter is a NULL_PTR, it indicates that the transmit data can be removed from the buffer immediately after it has been copied. Otherwise, the retry parameter must point to a valid RetryInfoType element. If TpDataState indicates TP_CONFPENDING, the previously copied data must remain in the TP buffer to be available for error recovery. TP_DATACONF indicates that all data that has been copied before this call is confirmed and can be removed from the TP buffer. Data copied by this API call is excluded and will be confirmed later. TP_DATARETRY indicates that this API call shall copy previously copied data in order to recover from an error. In this case TxTpDataCnt specifies the offset in bytes from the current data copy position.

[out]

availableDataPtr

Indicates the remaining number of bytes that are available in the upper layer module’s Tx buffer. availableDataPtr can be used by TP modules that support dynamic payload lengths (e.g. FrIsoTp) to determine the size of the following CFs.
Return type

BufReq_ReturnType

Return values

Name

Description

BUFREQ_OK

Data has been copied to the transmit buffer completely as requested.

BUFREQ_E_BUSY

Request could not be fulfilled, because the required amount of Tx data is not available. The lower layer module may retry this call later on. No data has been copied.

BUFREQ_E_NOT_OK

Data has not been copied. Request failed.

场景配置指南(Scenario Configuration Guide)¶

发送路由配置(Transmit Routing Configuration)

发送路由支持IF和TP两种方式，均支持1:1和1:N路由，为每一个PduRDestPdu配置一个PduRRoutingPath（1:N时N个Path共享同一PduRSrcPduRef）。

Transmit routing supports both IF and TP modes, both supporting 1:1 and 1:N routing. Configure one PduRRoutingPath per PduRDestPdu (in 1:N, N paths share the same PduRSrcPduRef).

  • IF发送：PduRRouteType = IF。上层调用 PduR_<Up>Transmit 或下层通过 PduR_<Lo>TriggerTransmit 请求发送。

    IF Tx: PduRRouteType = IF. Upper layer calls PduR_<Up>Transmit or lower layer triggers via PduR_<Lo>TriggerTransmit.

  • TP发送：PduRRouteType = TP。上层调用 PduR_<Up>Transmit，下层分片获取数据。

    TP Tx: PduRRouteType = TP. Upper layer calls PduR_<Up>Transmit; lower layer retrieves data segments.

接收路由配置(Receive Routing Configuration)¶

接收路由支持IF和TP两种方式，均支持1:1和1:N路由，IF额外支持N:1路由。为每一个PduRDestPdu配置一个PduRRoutingPath（1:N时N个Path共享同一PduRSrcPduRef）。

Receive routing supports both IF and TP modes, both supporting 1:1 and 1:N routing, with IF additionally supporting N:1 routing. Configure one PduRRoutingPath per PduRDestPdu (in 1:N, N paths share the same PduRSrcPduRef).

  • IF接收：PduRRouteType = IF。下层通过 PduR_<Lo>RxIndication 将接收报文传递给上层。

    IF Rx: PduRRouteType = IF. Lower layer forwards received messages to upper layer via PduR_<Lo>RxIndication.

  • TP接收：PduRRouteType = TP。下层通过 PduR_<LoTp>StartOfReception → PduR_<LoTp>CopyRxData → PduR_<LoTp>RxIndication 完成TP PDU接收流程。

    TP Rx: PduRRouteType = TP. Lower layer completes TP PDU reception via PduR_<LoTp>StartOfReception → PduR_<LoTp>CopyRxData → PduR_<LoTp>RxIndication.

网关路由配置(Gateway Routing Configuration)¶

网关路由支持IF和TP两种方式，均支持1:1、1:N、N:1路由。为每一个PduRDestPdu配置一个PduRRoutingPath（1:N时N个Path共享同一PduRSrcPduRef）。

Gateway routing supports both IF and TP modes, both supporting 1:1, 1:N, and N:1 routing. Configure one PduRRoutingPath per PduRDestPdu (in 1:N, N paths share the same PduRSrcPduRef).

  • IF网关：PduRRouteType = IF。PduRDestPduDataProvision = PDUR_TRIGGERTRANSMIT 时必须配置queue和PduRDefaultValueElement；PDUR_DIRECT时queue可选。

    IF Gateway: PduRRouteType = IF. When PduRDestPduDataProvision = PDUR_TRIGGERTRANSMIT, queue and PduRDefaultValueElement are required; optional for PDUR_DIRECT.

  • TP网关：PduRRouteType = TP。必须配置queue。可配置PduRTpThreshold实现on-the-fly gatewaying（1:N时同一PduRSrcPduRef最多一个Path配置阈值）。

    TP Gateway: PduRRouteType = TP. Queue is required. PduRTpThreshold enables on-the-fly gatewaying (max one path per PduRSrcPduRef in 1:N).

  2. PduRRoutingPath通过PduRRoutingPathGroupRef关联0..N个RoutingPathGroup

    PduRRoutingPath associates with 0..N RoutingPathGroups via PduRRoutingPathGroupRef

  3. PduRDestPdu在未关联任何RoutingPathGroup或关联的至少一个RoutingPathGroup使能时为Enable，否则Disable

    PduRDestPdu enabled when unassociated or associated with ≥1 enabled RoutingPathGroup; otherwise disabled

  4. 未关联任何RoutingPathGroup的PduRDestPdu初始化后永久Enable

    PduRDestPdu unassociated with any RoutingPathGroup remains permanently enabled after initialization
